v0.1.11 — since v0.1.10

A security and reliability follow-up to 0.1.10. If you are on 0.1.10, this is worth taking.

**Security**
- MangaDex chapter downloads now go through one bounded transport: the mirror URL MangaDex hands back is checked for embedded credentials and off-protocol ports, every redirect is re-checked rather than followed blindly, and the address actually connected to has to match the one that was approved. Previously only the first hostname was checked
- CBR/RAR conversion now reads each archive member's type and link target instead of just its name, so an archive can no longer smuggle a symlink or device node past the path check and write outside its own work folder. Member counts and sizes are bounded, and the extracted files are re-checked before anything is published
- The admin-only "show full paths" control on Queue now refuses when the record of that access cannot be written, instead of handing back the paths and reporting that it was recorded
- API keys are stripped from cross-origin redirects based on where the value came from, not just on a fixed list of header names, so a provider that puts its token in a custom header is covered too. Keys are also scrubbed from error text in the exact form a query string encodes them
- Every view that can carry filesystem paths and third-party client identifiers now applies the same redaction Queue does, rather than one route holding the line while others served the same fields

**Imports and matching**
- A file staged under a folder whose name happens to contain something like "c3" is no longer read as chapter 3. Unit identity now comes from the file and the release folder it arrived in, not from whatever temporary directory the download client used. This could quarantine a correct collected edition
- Fixed a crash in duplicate-issue cleanup that could stop the background sweep, when two workers cleaning the same duplicate group disagreed about which record to keep
- A mixed volume/chapter filename now needs evidence from inside the archive rather than a filename number match
- Duplicate queue rows for the same candidate are folded into one instead of accumulating
- A completed Soulseek transfer from weeks ago is no longer replayed as if it just finished
- A rejection that is already confirmed and unambiguous no longer goes to Manual Review for a decision that has already been made

**Interface**
- A failed row action no longer stays on screen after a newer action on another row has already succeeded, in either completion order
- System health findings now say what to do about them, and conditions that clear on their own are no longer badged as needing attention
