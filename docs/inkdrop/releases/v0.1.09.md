v0.1.09 — since v0.1.08

**Acquisition**
- SLSKD rejects wrong-subseries matches before downloading, not after
- New cbz/cbr tiebreak when candidates are otherwise equal
- Fixed .cbr files served as vnd.rar getting rejected outright
- Collected trades now satisfy individual issue wants directly
- Bigger search result limits, more candidates surfaced per search
- Manual Search no longer no-ops on back-to-back searches
- Manual Review's Reject & Search Again actually retries now, even through lock contention
- Manual Review accepts exact unresolved manga matches with a real approve path
- SLSKD recovery lanes get half of max_series instead of a third
- Fixed a priority gap that could strand a stuck import behind newer work
- Fixed an indexer-discovery query expansion gap
- Added a configurable cap on concurrent SLSKD transfers
- Import claims auto-release after a timeout instead of blocking forever
- Fixed the download-client handoff key not persisting, breaking retries
- Fixed staged SLSKD imports getting wrongly blocked when there's no live transfer ID to check
- Rebuilt import-verified notifications on a bounded pass — fixes duplicate/stale notifications and a real maintenance-sweep cost

**Direct download & Suwayomi**
- Added Pixeldrain, WeTransfer, and Buzzheavier as direct-download sources
- Fixed GetComics → Pixeldrain redirect resolution
- Suwayomi now under Download Clients, Test All runs in parallel
- Fixed Suwayomi/MangaDex staying hidden as unconfigured
- Fixed Suwayomi's connection status stuck on "Unknown" — every Test button now shows a real spinner and pass/fail

**Settings & backup**
- Scheduled full backups with automatic retention
- Settings export/import can carry encrypted credentials
- Added an OPDS discoverability panel
- Restore now shows the real failure reason instead of a bare "Bad Request"
- Filled in missing qBittorrent/SABnzbd field help, fixed Test closing the client editor mid-check

**Interface**
- Restored Wanted row selection for Search Selected and Manual Search
- Series pages render through the faster virtualized approach
